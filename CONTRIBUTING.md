# Contributing

Thanks for considering a contribution.

## Before you start

1. Read the project README and the relevant setup or architecture documentation.
2. Check existing issues and pull requests to avoid duplicating work.
3. For substantial changes, open an issue first to discuss the approach.

## Pull requests

- Keep each pull request focused and explain the problem it solves.
- Describe user-visible changes and include screenshots for UI changes when practical.
- Add or update tests for changed behaviour.
- Update documentation and environment examples when configuration changes.
- Never include real credentials, personal data, database dumps, or production secrets.
- Report which checks you ran and clearly note checks that could not be run.

## Quality checklist

- [ ] The change addresses a clear problem.
- [ ] Tests cover relevant behaviour.
- [ ] Formatting, type checks, and builds pass where available.
- [ ] Documentation reflects the actual implementation.
- [ ] No secrets or real personal data are included.
